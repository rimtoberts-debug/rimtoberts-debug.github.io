Lesson 7 of 8

Data Preprocessing
(HL)

Real data is messy. Learn how to clean, scale, encode and split it before any model sees it.

🎓GCSE & A-Level✓Free🧩simulations + quiz
Hook

A model is only as good as the data it is fed. Imagine a spreadsheet where one student is aged 150, two ages are blank, and 'M', 'male' and 'Male' all appear as different genders.

Data scientists often spend more time preparing data than building models.

Think: If you trained a model on that spreadsheet unchanged, what could go wrong?
Explanation

Cleaning the data

Missing values can be handled by dropping the rows (fine if few), or by imputing a replacement such as the mean, median or most common value. Outliers may be errors to remove or fix, or genuine rare cases worth keeping, so judgement is needed. Also remove duplicates and fix inconsistent formats (dates, spellings, units).

Always record what you changed. Quietly deleting awkward rows can introduce bias.

Explanation

Transforming the data

Normalisation (min-max scaling) squeezes values into a range such as 0 to 1: (x − min) ÷ (max − min). Standardisation (z-score) re-centres values to a mean of 0 and a standard deviation of 1: (x − mean) ÷ standard deviation. This stops large-valued features dominating distance-based or gradient-based models.

Encoding turns categories into numbers: label encoding for ordered categories, one-hot encoding for unordered ones.

Explanation

Choosing and splitting

Feature selection keeps the useful inputs and drops irrelevant or redundant ones, which cuts noise, training time and overfitting. Feature engineering creates new inputs, such as turning a date of birth into an age.

Split the data into training, validation and test sets before fitting anything. Work out scaling values (min, mean, standard deviation) from the training set only, then apply them to the other sets; using the test set earlier causes data leakage and over-optimistic results.

If one class is rare (fraud, disease), a model can look accurate by ignoring it. Remedies include collecting more minority examples, oversampling them, undersampling the majority, or choosing metrics such as recall.

Reflect

Questions worth thinking about

Using the test set would let information about unseen data leak into training, so the test score would look better than real-world performance.
If it is a genuine rare case, such as a real fraud or a record-breaking value, since removing it would hide the very thing the model needs to learn.
Summary

What to remember

  • Clean: missing values, outliers, duplicates, formats.
  • Scale: min-max or z-score so features are comparable.
  • Encode categories: label for ordered, one-hot for unordered.
  • Select features, then split; avoid data leakage.

Exam practice

Exam-style practice

Describe two preprocessing steps that should be carried out before training a model on customer data. [4 marks]

  • Handle missing values/outliers, e.g. impute with the median or remove errors (1 for step, 1 for description/reason)
  • Scale/normalise features so large-valued features do not dominate (1), or encode categories as numbers (1)

Explain why scaling should be fitted on the training data only. [3 marks]

  • Test data should represent unseen data (1)
  • Using its values to scale lets information leak into training (1)
  • This gives an over-optimistic test result (1)
